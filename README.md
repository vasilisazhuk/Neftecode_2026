# ⛽ Мультиагентная система (МАС) оптимизации производства товарного дизельного топлива Евро-5

Интеллектуальная система поддержки принятия решений оператора технологической цепочки:  
**«ЭЛОУ-АВТ-6 ➔ Установка гидроочистки 24-2000 ➔ Резервуарный блендинг ➔ Товарный парк»**.

Соответствует требованиям **ГОСТ 32511-2013 (EN 590:2009, экологический класс К5)**.

---

## 📌 Ключевые принципы и инженерные решения

1. **Приоритет безопасности и ГОСТ над экономикой:**
   * Содержание серы в товарном ДТ — **строго не более 10.0 мг/кг (≤ 10.0 мг/кг)**;
   * Температура вспышки в закрытом тигле — **не ниже 55.0 °C (≥ 55.0 °C)**;
   * Недопустимый или аварийный режим нельзя «компенсировать» более высокой производительностью.
2. **Защита от утечки данных во времени (Lookahead Bias Protection):**
   * Учтён физический регламентный лаг: лабораторные анализы ЛИМС становятся доступны советчику **только через 4 часа** после момента отбора пробы.
3. **Physics-Informed ML & Суррогатное моделирование:**
   * Поскольку в реальном архиве за 3.5 года 99.5% точек — это штатный безаварийный режим, обучение моделей выполнено на сбалансированной выборке цифрового двойника (30 000 технологических сценариев с авариями, дрейфами серы и отказами датчиков).
   * Встроены все официальные верифицированные формулы виртуальных анализаторов качества (ВАК).
4. **Регламентный отказ (Graceful Safety Fallback):**
   * При сбое поточных датчиков (ПАК) и устаревании лаборатории (> 18 ч) система отказывается от слепого управления и выдает предписание на ручной отбор проб.
5. **Автономность (Air-Gapped Ready):**
   * Система не требует подключения к внешнему интернету или облачным API и готова к развёртыванию в закрытом промышленном контуре предприятия.

## 🏛️ Архитектура мультиагентной системы

Система построена на взаимодействии 4 специализированных логических ролей:
### Роли агентов:
* **Агент Качества (`DataQualityAgent`):**
  * Иерархия источников истины: ЛИМС (контрольный факт) ➔ ПАК Q21 ➔ ВАК.
  * ML-классификатор состояния качества с оценкой вероятности (Confidence score).
* **Агент Надёжности (`ReliabilityAgent`):**
  * Мониторинг гидравлического сопротивления слоя катализатора Р-202 (перепад P8 ≤ 0.80 МПа) по закону Эргуна (dP ~ F²).
  * Контроль температуры слоя (T11 ≤ 385 °C) и квенча (F14).
* **Агент Оптимизации (`OptimizationAgent`):**
  * Управляет вектором: температура печи T6, расход сырья F9, газ отпарки W7, доли блендинга.
  * Имеет технологическую зону нечувствительности: **не дергает регуляторы в устойчивом режиме**.
  * Оптимизирует компромисс между топливом печи и цетаноповышающей присадкой (1 т присадки = 100 т ДТ).
* **Оркестратор (`Orchestrator`):**
  * Проверяет соблюдение жестких норм ГОСТ для смеси.
  * Формирует объяснение: *Причина ➔ Действие ➔ Ожидаемый эффект ➔ Ограничения*.

## 📂 Структура репозитория

```text
├── config/
│   └── settings.py              # Константы ГОСТ 32511-2013 (К5), лимиты КИП, экономика
├── data_pipeline/
│   ├── parser.py                # Парсинг русских дат, очистка числовых данных
│   └── synchronizer.py          # Временная склейка телеметрии и ЛИМС с 4-часовым лагом
├── models/
│   ├── vak_calculators.py       # Точные формулы ВАК установки 24-2000 и АВТ
│   ├── blending_engine.py       # Модель резервуарного смешения и присадок
│   └── saved_models/            # Предобученные ML-модели агентов (.joblib)
├── agents/
│   ├── base.py                  # Контракты и датаклассы обмена сообщениями
│   ├── quality_agent.py         # Агент Качества
│   ├── reliability_agent.py     # Агент Надёжности
│   ├── optimization_agent.py    # Агент Оптимизации (Парето-поиск)
│   └── orchestrator.py          # Оркестратор системы
├── dashboard/
│   └── app.py                   # Интерактивный дашборд оператора на Streamlit
├── tests/
│   └── test_vak_precision.py    # Автотесты формул ВАК по эталонам организаторов
├── resources/                   # Папка для исходных датасетов (исключена из Git)
├── train_models.py              # Скрипт генерации данных и переобучения ML-моделей
├── main.py                      # Консольный прогон 3 обязательных сценариев ТЗ
├── run_history.py               # Консольный запуск МАС на реальных срезах архива телеметрии
├── requirements.txt             # Зависимости проекта
└── .gitignore                   # Защита от попадания тяжелых файлов данных в репозиторий
```

## 🚀 Инструкция по установке и запуску

### 1. Клонирование репозитория и настройка окружения
```bash
git clone https://github.com/vasilisazhuk/Neftecode_2026.git
cd Neftecode_2026

# Создание виртуального окружения Python (рекомендуется Python 3.10–3.12)
python -m venv .venv

# Активация окружения:
# Windows (PowerShell):
.venv\Scripts\Activate.ps1
# Windows (cmd):
.venv\Scripts\activate.bat
# Linux / macOS:
source .venv/bin/activate

# Установка всех зависимостей проекта
pip install -r requirements.txt
```
### 2. Размещение данных (для работы с реальным архивом)
Создайте в корне проекта папку `resources/` (если она еще не создана) и поместите туда файлы из архива хакатона:
```text
resources/
├── avt_tags.csv                          # Телеметрия участка АВТ
├── 242000_tags.csv                       # Телеметрия установки 24-2000 (ГО ДТ)
├── Выгрузка ПАК 01.01.2023 - н.в_.xlsx    # Поточные анализаторы серы и плотности
└── ЛИМСы 01.01.2023 - н.в_ (2).xlsx      # Лабораторные анализы качества
```
### 3. Автоматическая проверка формул ВАК (Unit-тесты)
Запуск верификации математических моделей виртуальных анализаторов по эталонам организаторов:
```bash
pytest tests/test_vak_precision.py -v
```
Тест проверяет совпадение расчетов по всем формулам разгонки (T50, T90, T95), вспышки и плотности D15 с эталонными числовыми примерами из ТЗ с точностью до 0.1.
### 4. Консольная демонстрация обязательных сценариев ТЗ:
Быстрый запуск и проверка логики всех 4 агентов без графического интерфейса:
```bash
pytest tests/test_vak_precision.py -v
```
Скрипт поочередно прогоняет 3 обязательных сценария из ТЗ:
* **Штатный устойчивый режим**: параметры в нормальном коридоре, система подтверждает безопасность и не создает лишних управляющих действий.
* **Риск выхода за спецификацию**: сера в ГОДТ выросла до 9.4 мг/кг. МАС формирует управляющее воздействие на печь Т6 и рассчитывает прогнозное качество смеси.
* **Регламентный отказ (Safety Fallback)**: поточный датчик Q21 отключен, а лаборатория ЛИМС старше 36 часов. Оркестратор отказывается от слепого управления и требует ручного забора проб.

### 5. Консольный прогон на реальной истории телеметрии
Проверка работы системы на реальных точках завода из архива телеметрии:
```bash
python run_history.py
```
Скрипт собирает в единый датасет 189 000 строк с учетом 4-часового лага лаборатории, выбирает контрольную временную точку и выводит подробное решение Оркестратора в формате JSON.

### 6. Запуск интерактивного дашборда оператора
Проверка работы системы на реальных точках завода из архива телеметрии:
```bash
streamlit run dashboard/app.py
```
После запуска в браузере откроется страница по адресу ``http://localhost:8501``.

#### Возможности дашборда:

* **Реальный архив телеметрии**: навигация слайдером по 189 000 точкам истории, интерактивный график тренда серы с линией ГОСТ (10 мг/кг) и мгновенный анализ среза времени.
* **Ручной ввод установок**: возможность задать любые значения КИП (T6, F9, W7, серу, вспышку, перепад) для стресс-тестирования логики агентов.
* **Интерактивный симулятор блендинга**: ползунки долей компонентов (ГОДТ, керосин, газойль) и цетаноповышающей присадки с мгновенным пересчетом качества товарного дизеля в резервуаре.

## 🔬 Обучение и веса ML-моделей

В репозиторий уже включены предобученные веса моделей агентов в папке `models/saved_models/`:

* `reliability_model.joblib` — классификатор состояния катализатора и оборудования;
* `action_policy_model.joblib` — модель выбора стратегии управления.

При необходимости переобучить модели на расширенном пространстве сценариев цифрового двойника запустите:
```bash
python train_models.py
